> **Audience:** You / a junior dev shipping the Lovable export to Vercel.
> **Goal:** Take the project at [website/lovable/](website/lovable/) and put it live on Vercel.
> **Time:** ~30 min total, ~20 min of code surgery + ~10 min of platform setup.
> **Companion docs:** [PLAN-WEBSITE2.md](PLAN-WEBSITE2.md) (the source-of-truth marketing site plan), [WEBSITE-PROMPT.md](WEBSITE-PROMPT.md) (the design brief).

## 1. The problem in one paragraph

Lovable exported the site as a **TanStack Start app targeting Cloudflare Workers**, not a static site. The `npm run build` produces `dist/server/` (a Worker bundle with `worker-entry.js` and `wrangler.json`) plus `dist/client/` that has **no `index.html`**. Vercel can't run Cloudflare Workers and can't serve an `index.html`-less directory, so a direct push will deploy but not work.

The site uses **no actual server functions** (verified — no `createServerFn`, no API routes, just an SSR error wrapper for branded 500 pages). So all the SSR machinery is solving a problem we don't have. Strip it, and we get a plain Vite SPA that Vercel deploys cleanly.

---

## 2. Two paths (pick one)

### Path A — **Convert to plain Vite SPA, deploy to Vercel** (recommended)
Keep TanStack Router as the SPA router. Drop TanStack Start, the Cloudflare plugin, and the Lovable wrapper. Add an `index.html` and a `main.tsx` mount point. Site behaves identically; build output is normal Vite static files.

- **Pros:** Predictable, well-trodden, fits Vercel's Vite preset perfectly. Future-friendly.
- **Cons:** ~20 min of file edits.

### Path B — **Deploy to Cloudflare Pages instead** (skip Vercel)
The project is already wired for this. Run `wrangler deploy` and you're live. No code changes.

- **Pros:** 2 minutes. Zero risk.
- **Cons:** Not Vercel.

This plan covers **Path A**.

## 4. The Path A surgery — step by step

### Step 1 — Branch off (safety)

```bash
cd website/lovable
git checkout -b vercel-spa
```

### Step 2 — Delete the SSR scaffolding

```bash
rm src/server.ts src/start.ts wrangler.jsonc bun.lock
```

These three files exist only to support Cloudflare Worker SSR. The `bun.lock` deletion is optional but reduces lockfile-conflict noise; we'll standardise on `package-lock.json`.

### Step 3 — Create `index.html` at the project root

This is the static HTML Vite serves. The `<div id="root">` is where React mounts; the `<script>` boots the app.

```html
<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />
    <meta name="theme-color" content="#47E865" />
    <meta name="description" content="Qloqal turns any small business into an online shop. Customers order in the app; you take orders right on WhatsApp." />
    <link rel="preconnect" href="https://fonts.googleapis.com" />
    <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
    <link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700&family=Plus+Jakarta+Sans:wght@600;700;800&display=swap" rel="stylesheet" />
    <title>Qloqal — Run your shop on WhatsApp</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.tsx"></script>
  </body>
</html>
```

### Step 4 — Create `src/main.tsx` (the React mount point)

Replaces what TanStack Start's server-entry was doing.

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { RouterProvider } from "@tanstack/react-router";
import { QueryClientProvider } from "@tanstack/react-query";
import { HelmetProvider } from "react-helmet-async";
import { getRouter } from "./router";
import "./styles.css";

const router = getRouter();
// router.context.queryClient is set inside getRouter — pull it back out for the provider
const queryClient = router.options.context!.queryClient;

declare module "@tanstack/react-router" {
  interface Register {
    router: typeof router;
  }
}

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <HelmetProvider>
      <QueryClientProvider client={queryClient}>
        <RouterProvider router={router} />
      </QueryClientProvider>
    </HelmetProvider>
  </StrictMode>,
);
```

### Step 5 — Trim `src/routes/__root.tsx`

The current file imports `HeadContent` and `Scripts` from `@tanstack/react-router` (they render HTML head + script tags during SSR). For SPA we don't need them — the `index.html` already has the head and the script. Open the file and:

- Remove `HeadContent` and `Scripts` from the import
- Remove their JSX usage in the root component (they typically appear in a `<head>` / before `<Outlet />`)
- Remove `import appCss from "../styles.css?url";` and any related `<link href={appCss} />` — we already import `styles.css` in `main.tsx`

The `QueryClientProvider` and `HelmetProvider` that may currently wrap the outlet here can stay — but since we're providing them in `main.tsx`, you can simplify and let the root just render `<Outlet />` plus any header/footer chrome. Either way works.

### Step 6 — Replace `vite.config.ts`

```ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { TanStackRouterVite } from "@tanstack/router-plugin/vite";
import tsconfigPaths from "vite-tsconfig-paths";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [
    TanStackRouterVite({
      routesDirectory: "./src/routes",
      generatedRouteTree: "./src/routeTree.gen.ts",
      autoCodeSplitting: true,
    }),
    react(),
    tsconfigPaths(),
    tailwindcss(),
  ],
  server: { port: 5173 },
});
```

Drops the Lovable wrapper entirely. Uses the same plugins it baked in (router, react, tsconfig paths, tailwind), minus Cloudflare.

### Step 7 — Update `package.json`

Remove these dependencies:

```
@cloudflare/vite-plugin
@tanstack/react-start
@tanstack/router-plugin       (move from deps to devDeps)
@lovable.dev/vite-tanstack-config
```

Add (or move to) **devDependencies:**

```
@tanstack/router-plugin       (the Vite plugin)
@vitejs/plugin-react
vite-tsconfig-paths
@tailwindcss/vite
```

Update the `scripts` block:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview",
    "lint": "eslint .",
    "format": "prettier --write ."
  }
}
```

(Drop the `build:dev` script — not needed for production deploy.)

### Step 8 — Add `vercel.json`

Mirrors the pattern from [qloqal-website2/vercel.json](qloqal-website2/vercel.json):

```json
{
  "rewrites": [{ "source": "/(.*)", "destination": "/" }],
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "X-Frame-Options", "value": "DENY" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=()" }
      ]
    }
  ]
}
```

The `rewrites` rule sends every URL to `/` so React Router handles client-side routes. Without it, hitting `/vendors` directly would 404.

### Step 9 — Reinstall and test locally

```bash
rm -rf node_modules dist package-lock.json
npm install
npm run build
npm run preview
```

Open the preview URL (Vite prints it — usually http://localhost:4173). Click through every route. Check the console for errors.

**Expected build output:** `dist/` containing `index.html` + `assets/`. **No** `dist/server/` directory. **No** `wrangler.json`.

If the build fails, the most likely culprits are:
- A leftover import from `@tanstack/react-start` in a route file (search and remove)
- A leftover `HeadContent` / `Scripts` reference in `__root.tsx`
- Tailwind v4 missing `@import "tailwindcss"` at the top of `styles.css` (Tailwind v4 uses CSS-based config, not JS config)

### Step 10 — Commit + push

```bash
git add -A
git commit -m "Convert TanStack Start → Vite SPA for Vercel deploy"
git push -u origin vercel-spa
```

If there's no remote yet:

```bash
gh repo create qloqal-lovable --private --source=. --remote=origin --push
```

## 5. Vercel deploy

### Step 11 — Import on Vercel

1. Go to [vercel.com/new](https://vercel.com/new)
2. Import the GitHub repo
3. **Framework preset:** Vite (auto-detected)
4. **Root directory:** `website/lovable` (since the repo root is `qloqal/`, not the lovable folder)
5. **Build command:** `npm run build` (default)
6. **Output directory:** `dist` (Vite default)
7. **Install command:** `npm install`

### Step 12 — Environment variables

This site uses no env vars at runtime — but if you later add a contact form via Web3Forms, add `VITE_WEB3FORMS_KEY` in Vercel → Settings → Environment Variables (Production, Preview, Development scopes).

### Step 13 — Deploy

Click *Deploy*. Wait ~2 min. Vercel produces a URL like `qloqal-lovable.vercel.app`.

### Step 14 — Custom domain (optional)

In Vercel → Domains, add `qloqal.com` and follow the DNS instructions:
- `A` record → `76.76.21.21`
- `CNAME` for `www` → `cname.vercel-dns.com`

Vercel auto-issues Let's Encrypt SSL.

## 7. Common gotchas

| Symptom | Cause | Fix |
|---|---|---|
| Direct URL like `/vendors` returns 404 in production | Missing SPA rewrite | Confirm `vercel.json` is committed and at the deploy root |
| Build fails with "Cannot find module @tanstack/react-start" | A route still imports from it | Search `src/` for `@tanstack/react-start` and remove |
| Build succeeds but blank page in browser | `main.tsx` not loaded | Confirm `index.html` references `/src/main.tsx` and `<div id="root">` exists |
| Tailwind classes don't work after build | Tailwind v4 needs `@import "tailwindcss";` at the top of `styles.css` | Add the import; also confirm `@tailwindcss/vite` plugin is in `vite.config.ts` |
| `routeTree.gen.ts` import errors | Plugin didn't regenerate the file | Run `npm run build` once or `vite dev`; the plugin writes the file on first run |
| Vercel build "command not found: tsc" | TypeScript only in devDependencies and Vercel skipped them | Vercel installs devDeps by default; double-check `package.json` and the install log |
